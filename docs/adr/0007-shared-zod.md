# ADR-0007: Zod-схемы в shared как контракт API

Статус: принято («пока») · 2026-11-17

## Контекст

Фронт отправляет данные, бэк их принимает. Если тип описан дважды, поля расходятся (например, `lang` и `language`), и ошибка видна только при запуске. Типы TypeScript не проверяют данные, которые реально пришли по сети.

## Решение

Пакет `@writechart/shared` с Zod-схемами, типами из них (`z.infer`) и константами. Пакет без сборки (Just-in-Time): `exports` указывают на `.ts`-исходники. Импорт по подпутям, без barrel-файлов.

## Варианты

- **Только TypeScript-типы.** Нет проверки данных во время работы.
- **OpenAPI + генерация кода.** Лишний шаг генерации.
- **Собираемый пакет (Compiled).** Есть кэш сборки, но больше настройки; для маленького пакета не нужно.

## Последствия

- Одна схема проверяет форму на фронте и запрос на бэке.
- В `shared` нельзя код, зависящий от браузера или Node.
- Если пакет вырастет, можно перейти на Compiled.
