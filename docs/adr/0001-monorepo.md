# ADR-0001: Монорепозиторий frontend / backend / shared

Статус: принято · 2026-11-17

## Контекст

Команда из 4 человек делает один продукт: SPA и API. Фронту и бэку нужны общие типы и правила проверки данных. Агентам удобнее, когда весь код и инструкции лежат в одном месте. Преподаватель смотрит вклад каждого по истории репозитория.

## Решение

Один репозиторий, три пакета Yarn workspaces в корне: `frontend/`, `backend/`, `shared/`.

## Варианты

- **Два репозитория (фронт и бэк отдельно).** Общие типы пришлось бы публиковать пакетом или копировать; правка API и UI разъезжалась бы на два PR. Mattermost разделял репозитории в 2017 году и позже слил их обратно в один.
- **Раскладка `apps/` + `packages/` (как в документации Turborepo).** Удобнее, когда пакетов много. Для трёх пакетов прямые имена папок понятнее.

## Последствия

- Одна правка API и UI — один PR.
- Общий код подключается как `workspace:*`, без публикации.
- CI должен уметь запускать только изменившиеся пакеты: для этого Turborepo (ADR-0005).
