# ADR-0015: Логи бэка — pino и pino-http

Статус: принято · 2026-11-20

## Контекст

Бэку нужны логи: старт и остановка сервера, каждый HTTP-запрос, ошибки со стеком. Чтобы связать строки одного запроса, у запроса нужен свой id. На проде логи читает сборщик, ему удобен JSON в stdout (так советует nodebestpractices). В dev человеку удобнее цветной текст.

## Решение

- **pino** — логгер. `backend/src/lib/logger.ts`: `createLogger({ level, pretty })`. Уровень берётся из `LOG_LEVEL` (по умолчанию `info`).
- **pino-http** — лог HTTP-запросов. У каждого запроса id: берётся из заголовка `x-request-id`, если он пришёл, иначе `randomUUID()`; id уходит в ответ заголовком `X-Request-Id`. Опросы `/api/health` и `/api/health/ready` в лог не пишутся.
- **pino-pretty** — только в dev (`NODE_ENV=development`), как транспорт pino в отдельном потоке. Это dev-зависимость; на проде (бандл Vite, [ADR-0014](0014-backend-build-and-runtime.md)) пишется только JSON.
- Код пишет в лог через `req.log` (с id запроса) или общий логгер, не через `console`. Исключение — ошибка переменных окружения на старте, когда логгера ещё нет.

## Варианты

- **winston.** Популярен, много транспортов. Медленнее pino, а лог HTTP-запросов — отдельный пакет `express-winston`, который используют мало.
- **morgan.** Только строка на запрос, без общего логгера приложения и без JSON по умолчанию.
- **`console`.** Без уровней, без JSON и без id запроса.
- Скачивания npm за неделю (20.11.2026): pino — 81,8 млн, winston — 37,5 млн, pino-http — 9,8 млн, express-winston — 0,7 млн.

## Последствия

- Один формат логов (JSON) для всего бэка, у строк запроса общий `reqId`.
- В dev нужен `pino-pretty` в `devDependencies`; в бандл он не попадает, потому что транспорт включается только в dev.
- Мониторинг, который опрашивает health-адреса, не засоряет лог.
