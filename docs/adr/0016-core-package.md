# ADR-0016: Ядро схем в пакете `core`

Статус: принято · 2026-11-22

## Контекст

Главная функция Writechart — блок-схема по ГОСТ 19.701-90 из кода. Код, который её строит (ядро), нужен фронту сейчас и бэку потом: экспорт, проверка по ГОСТ, API. В первой версии схема строится в браузере: без задержки сети на каждое изменение кода и без нагрузки на свои серверы (решения человека на грилинге 21.11.2026).

Подходящего места нет: в `shared/` по правилам только Zod-схемы, типы и константы ([ADR-0007](0007-shared-zod.md)), а из `frontend/` бэку импортировать нельзя.

Замер 21.11.2026, TypeScript 7.0.2: `tsconfig` с `lib: ["ES2024"]` даёт ошибку на `document` (TS2584), `process` (TS2591), `TextEncoder` и `structuredClone` (TS2304).

## Решение

- **Пакет `core/` (`@writechart/core`)** — отдельный воркспейс, без сборки, как `shared/`: `exports: { "./*": "./src/*.ts" }`, импорт по подпутям.
- **Ни DOM, ни Node в типах:** `lib: ["ES2024"]` и `types: []` в `core/tsconfig.json`. Обращение к API браузера или Node ломает `yarn typecheck`.
- **Всё, что зависит от среды, ядро получает аргументом:** парсер, загрузку wasm, файлы, таймеры.
- **Правила синтаксиса Node**, как в `shared/` ([ADR-0014](0014-backend-build-and-runtime.md)): импорт своих файлов с `.ts`, `import type`, без `enum`, `namespace` с кодом и parameter properties. Бэк в dev исполнит ядро через Node без сборки.
- Тесты — Vitest без конфига, окружение `node`.

## Варианты

- **В `shared/`.** Там только схемы, типы и константы; с ядром пакет станет свалкой, а фронт и бэк будут тянуть всё вместе.
- **В `frontend/src/`.** Бэку импортировать из фронта нельзя; перенос потом — большой переезд.
- **Строить схему на бэке.** Задержка сети на каждое изменение кода и нагрузка на свои серверы.
- **Правило Oxlint вместо `lib`.** Линтер ловит глобальные имена, но не типы; `lib` закрывает и то и другое.
- **Своя сборка пакета (`tsc`, tsdown).** Фронт и бэк и так собирает Vite, в dev Node стирает типы сам; `dist/` потребовал бы `build` перед `typecheck` и `test`.

## Последствия

- Ещё один воркспейс; `turbo.json` и CI не меняются: `typecheck` и `test` подхватывают его сами.
- В ядре нет и общих API (`TextEncoder`, `structuredClone`, `URL`, `console`). Нужное объявляется точечно с записью в `core/AGENTS.md`.
- Данные ядра, которые пойдут по API, всё равно описываются Zod-схемой в `shared/`.
- Остальные решения ядра (парсер, модель, раскладка, SVG) — отдельные ADR в изменении `add-flowchart-python`.
