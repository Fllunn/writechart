# ADR-0005: Yarn 4 (node-modules) + Turborepo

Статус: принято · 2026-11-17

## Контекст

Монорепо из трёх пакетов (ADR-0001). У всех 4 человек и в CI должна быть одна версия менеджера пакетов. Задачи (сборка, тесты, линт) нужно запускать по порядку зависимостей и не повторять, если код не менялся.

## Решение

- **Yarn 4.18.1** — последняя стабильная версия на 17.11.2026 (тег `latest` в npm). Закреплена через `packageManager` в `package.json` и включается Corepack.
- **`nodeLinker: node-modules`** — обычная папка `node_modules`.
- **Turborepo** — запуск задач по всем пакетам с кэшем (будет установлен отдельным изменением).

## Варианты

- **Yarn Classic 1.x.** Заморожен, принимает только исправления безопасности.
- **Yarn 6.** Переписывается на Rust, пока превью.
- **Plug'n'Play (по умолчанию в Yarn 4).** Быстрее и строже, но часть инструментов с ним не работает (известные проблемы у Vitest, Storybook, React Native). Babel и Jest на Yarn 4 тоже используют `node-modules`.
- **Nx.** Мощнее, но сложнее, для трёх пакетов избыточен.
- **Без диспетчера задач.** Проще, но без кэша и порядка зависимостей.
- Скачивания в npm за неделю 09–15.11.2026: turbo — 45,2 млн, nx — 14,6 млн, lerna — 1,9 млн.

## Последствия

- Строгость PnP (нельзя импортировать необъявленный пакет) заменим правилом ESLint.
- Нужен `corepack enable` (в Node 24 Corepack входит в поставку).
