# ADR-0017: Парсер кода — tree-sitter

Статус: принято · 2026-11-22

## Контекст

Writechart строит блок-схему по коду: сначала Python, потом JS, TS, C, C++, C#, Java, Go, Rust, Pascal и псевдоязык. Код разбирается в браузере, на каждое нажатие клавиши, и почти всегда содержит ошибку: студент ещё печатает. Ядро схем ([ADR-0016](0016-core-package.md)) не зависит от среды, поэтому парсер передаётся ему снаружи.

Нужно: грамматики для всех языков из списка, разбор за миллисекунды, понятное поведение на незаконченном коде, живое сопровождение.

## Решение

**tree-sitter**: `web-tree-sitter` (wasm) и официальные грамматики (`tree-sitter-python` и т. д.). Решение человека на грилинге 21.11.2026: важнее опытная команда и доверие сообщества (≈27 тыс. звёзд, 8 сопровождающих), чем вес.

- Разбор идёт в Web Worker фронта; wasm грузится там же, `?url`-импортом с нашего же адреса.
- Ядро получает корень дерева через свой интерфейс узла (`core/src/languages/syntax-node.ts`) и `web-tree-sitter` не импортирует.
- Нативная часть грамматик не собирается: `dependenciesMeta: { "tree-sitter-python": { "built": false } }` в корневом `package.json`.

## Варианты

- **Lezer** (`@lezer/python`). Легче в 3 раза, та же скорость. Но грамматики Pascal нет, грамматик для части языков меньше и их сопровождает в основном один человек.
- **ANTLR.** Грамматики есть почти для всего, но рантайм для JS тяжёлый, восстановление после ошибок при наборе слабее, дерево надо обходить своими визиторами под каждую грамматику.
- **Свой парсер.** Полный контроль над сообщениями об ошибках, но 10 языков — годы работы.

Замеры на грилинге 21.11.2026 (Node 24.22, Windows):

| Что | tree-sitter (`web-tree-sitter` 0.27.2 + `tree-sitter-python` 0.25.0) | Lezer (`@lezer/python`) |
|---|---|---|
| вес gzip | JS 32 КБ + wasm ядра 83 КБ + wasm Python 65 КБ ≈ 180 КБ | 56 КБ |
| разбор 1000 строк | 6,6 мс | ≈ 7 мс |
| разбор 10 строк | 0,13 мс | — |
| загрузка wasm | 25 мс | не нужна |
| Pascal | грамматика Isopod/tree-sitter-pascal (MIT), wasm собираем сами; пакет на npm заброшен | нет |

Ошибки при наборе (замер 22.11.2026): без `:` после `if` или `while` tree-sitter даёт узел `ERROR`, а не пропущенный `:`; на незакрытой скобке ошибка тянется до конца файла. Поэтому любая ошибка разбора — новой схемы нет, на экране последняя удачная, а «не хватает «:»» ядро находит само по строкам кода.

## Последствия

- Страница тяжелее на ≈ 180 КБ gzip для Python; грамматика каждого следующего языка — свой wasm, грузить его только при выборе языка.
- В `web-tree-sitter` есть прямой `eval` (код Emscripten). Сборка Vite предупреждает о нём; CSP страницы нужно проверить на нём при деплое.
- Сообщения об ошибках зависят от того, как грамматика восстанавливается после ошибки: точные сообщения («не хватает «:»») — своя логика в конвертере языка.
- Смена парсера не трогает раскладку и SVG: меняется только конвертер `languages/<язык>.ts`.
