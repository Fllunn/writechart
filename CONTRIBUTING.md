# Как работать в команде

Правила для людей. Правила для агентов: [`AGENTS.md`](AGENTS.md). Причины решений: [ADR-0019](docs/adr/0019-team-process.md).

## Задачи

Задачи живут в GitHub Issues и на доске GitHub Projects проекта.

- **Один issue = одно изменение OpenSpec = одна ветка = один PR.** Строки `tasks.md` в issue не копируй.
- Если работа велика для одного человека, раздели её на несколько изменений OpenSpec, у каждого свой issue.
- Ролей нет: любой берёт любую задачу. Сроков и вех тоже нет.

## Путь задачи по доске

Задача проходит доску один раз. Proposal и код лежат в одной ветке и уходят одним PR.

| Этап | Колонка | Кто двигает |
|---|---|---|
| Идея, никто не взял | Backlog | любой |
| Агент пишет proposal (`/opsx:propose`), ты читаешь и утверждаешь его агенту; агент пишет код по `tasks.md` (`/opsx:apply`) | In progress | автор |
| PR (proposal + код) ждёт approve и CI | In review | автор |
| PR слит | Done | GitHub сам, по `Closes #N` |

## Как взять задачу

1. Поставь себя в **Assignee** и переведи карточку в **In progress**.
2. Только потом создавай ветку от `master`: `<тип>/<имя-изменения>`, например `feat/add-flowchart-cpp`.
3. Если у задачи уже есть исполнитель, не трогай её: напиши ему.

## PR

- В тексте PR пиши `Closes #N` (раздел «Задача» в шаблоне). Тогда после слияния issue закроется сам.
- Коммиты по Conventional Commits со scope: `feat(core): add cpp parser`. Типы и примеры: [`AGENTS.md`](AGENTS.md#процесс).

## Ревью

- Proposal утверждает **автор задачи** своему агенту, до кода. PR для этого не нужен.
- PR целиком (proposal + код) утверждает **любой член команды, кроме автора**: approve на PR.
- Без approve PR не сливается: так настроен ruleset `master`.
- Нужен ревьюер — попроси кого-нибудь из команды.

## Слияние

1. Есть approve, CI зелёный, ветка актуальна («Update branch», если `master` ушёл вперёд).
2. Автор архивирует изменение (`/opsx:archive <имя>`) в той же ветке и коммитит архив последним коммитом.
3. Если approve после этого сбросился, ревьюер ставит его заново: в коммите с архивом меняется только `openspec/`.
4. **Сливает автор:** кнопка GitHub, режим merge commit.

## Метки

| Группа | Метки |
|---|---|
| Пакет | `core`, `frontend`, `backend`, `shared`, `e2e`, `ci`, `docs` |
| Тип | `feat`, `fix`, `chore` |

Метки ставит тот, кто заводит issue. Форма issue их не ставит.
