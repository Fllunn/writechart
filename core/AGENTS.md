# AGENTS.md — core

Сначала прочитай корневой [`../AGENTS.md`](../AGENTS.md): процесс OpenSpec и правила Git действуют и здесь.

## Что здесь

Ядро схем: код программы → блок-схема по ГОСТ 19.701-90 в SVG. Сейчас ядро импортирует фронт (схема строится в браузере, в Web Worker), позже тот же код запустит бэк: экспорт, проверка по ГОСТ, API. Почему отдельный пакет — [ADR-0016](../docs/adr/0016-core-package.md), как устроен конвейер — [ADR-0018](../docs/adr/0018-flowchart-pipeline.md).

Пакет без сборки: `exports` в `package.json` указывают на исходники `.ts` в `src/`, их компилирует тот, кто импортирует.

## Конвейер `src/`

Дерево разбора → структура → чертёж → SVG. Каждый шаг — свой модуль, тесты — рядом.

| Модуль | Что делает |
|---|---|
| `flowchart.ts` | вход для фронта: дерево + параметры → `{ svg, warnings, errors }` |
| `languages/syntax-node.ts` | интерфейс узла дерева, который ядро берёт у парсера |
| `languages/python.ts` | дерево `tree-sitter-python` → структура; ошибки разбора, предупреждения, лимиты |
| `notation.ts` | выражения Python → математическая запись (`≤`, `mod`, `⌊a / b⌋`, степень надстрочно) |
| `structure.ts` | типы структуры: шаги, текст частями, `Diagnostic` |
| `limits.ts` | лимиты размера и их сообщения |
| `symbols.ts` | размеры фигур от текста и кегля, перенос строк поровну |
| `layout.ts` | структура → чертёж (вложенные коробки), значения по умолчанию, правило стрелок |
| `drawing.ts` | типы чертежа, правило стрелок по умолчанию |
| `render-svg.ts` | чертёж → строка SVG |
| `svg-builder.ts` | строитель SVG с белым списком |
| `gost-check.ts` | чертёж → список нарушений правил ГОСТ |
| `fonts/` | ширины букв: тип `FontMetrics`, таблица Tinos |
| `test-support/` | только для тестов: разбор Python в Node, программы-примеры; закрыт в `exports` (`"./test-support/*": null`) |

Новый язык — новый конвертер в `languages/` в ту же структуру; раскладку и SVG он не трогает.

## Правила папки

- Пиши код, который одинаково работает в браузере и в Node. `tsconfig.lib.json` (код `src/`) задаёт `lib: ["ES2024"]` и `types: []`, поэтому `document`, `process`, `fs`, `setTimeout` ломают `yarn typecheck`. Тесты, `src/test-support/` и `scripts/` проверяет `tsconfig.test.json` с типами Node. Пакеты не из `package.json` этой папки, например React, ловит `yarn deps`.
- Нужен API, общий для браузера и Node (`TextEncoder`, `structuredClone`, `URL`, `console`), — объяви его тип точечно и запиши сюда, какой и зачем.
- Парсер и всё, что зависит от среды (загрузку wasm, файлы, таймеры), ядро получает аргументом от вызывающего. Дерево разбора приходит как `SyntaxNode`: узел `web-tree-sitter` подходит по структуре, импортировать `web-tree-sitter` в `src/` нельзя (он только в dev-зависимостях для тестов).
- Синтаксис — тот, что Node исполняет без сборки: импорт своих файлов с `.ts`, типы через `import type`, только стираемый TypeScript (без `enum` и свойств в параметрах конструктора), его проверяет `erasableSyntaxOnly` ([ADR-0014](../docs/adr/0014-backend-build-and-runtime.md)). Бэк в dev будет исполнять ядро так.
- Каждый модуль — свой подпуть: `@writechart/core/flowchart`. Общий `index.ts` с `export *` не заводи.
- Зависимости идут в одну сторону: фронт и бэк импортируют ядро, ядро берёт только свои файлы.
- Модель схемы, которая пойдёт по API, описывай Zod-схемой в `shared/`; ядро работает со своими типами.
- Тесты — `*.test.ts` рядом с кодом.
- Невидимые символы (смена направления U+202A–U+202E и U+2066–U+2069, U+FFFD) пиши кодом: `String.fromCodePoint(0x202e)`, `` new RegExp(String.raw`…`) ``. oxfmt раскрывает escape `\u202E` в строках и регулярных выражениях в сам символ, и в исходнике он становится невидимым.

## SVG — только через строитель

Разметку SVG собирает `el(имя, атрибуты, дети)` из `svg-builder.ts`: элементы и атрибуты из белого списка, текст и значения экранируются, символы смены направления текста становятся меткой `⟨U+202E⟩`. Новый элемент или атрибут — правка белого списка и теста атак в `svg-builder.test.ts`. Текст пользователя в SVG попадает только ребёнком-строкой `el`, шаблонная строка с ним — дыра XSS.

## Эталонные SVG

`src/snapshots.test.ts` сравнивает SVG программ из `src/test-support/examples.ts` с файлами `src/__snapshots__/*.svg` (`toMatchFileSnapshot`). Правка раскладки или отрисовки меняет эталоны — это и цель: разница видна в PR, человек принимает её глазами. После намеренной правки:

```bash
yarn workspace @writechart/core test -u
```

Новый пример в `examples.ts` получает эталон и проверку `gost-check` автоматически.

## Таблица шрифта

`src/fonts/tinos.ts` сгенерирован, руками не правь. Перегенерировать (после обновления `@fontsource/tinos` или смены набора символов):

```bash
cd core
node scripts/generate-font-metrics.ts
cd ..
yarn format
```

Скрипт читает WOFF латиницы и кириллицы (начертание 400) через `opentype.js`. Ширины знаков, которых нет в `@fontsource/tinos` (`≤ ≥ ≠ ⌊ ⌋ ⟨ ⟩`), заданы в скрипте константами, замеренными в Chromium. После перегенерации проверь `yarn workspace @writechart/core test`: эталоны SVG покажут, что сдвинулось.
