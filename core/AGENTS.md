# AGENTS.md — core

Сначала прочитай корневой [`../AGENTS.md`](../AGENTS.md): процесс OpenSpec и правила Git действуют и здесь.

## Что здесь

Ядро схем: код программы → блок-схема по ГОСТ 19.701-90. Пока пакет пустой: код ядра появится в изменении `add-flowchart-python`. Первым ядро будет импортировать фронт (схема строится в браузере), позже тот же код запустит бэк: экспорт, проверка по ГОСТ, API. Почему отдельный пакет — [ADR-0016](../docs/adr/0016-core-package.md).

Пакет без сборки: `exports` в `package.json` указывают на исходники `.ts` в `src/`, их компилирует тот, кто импортирует.

## Правила папки

- Пиши код, который одинаково работает в браузере и в Node. `tsconfig.json` задаёт `lib: ["ES2024"]` и `types: []`, поэтому `document`, `process`, `fs`, `setTimeout` ломают `yarn typecheck`. Пакеты не из `package.json` этой папки, например React, ловит `yarn deps`.
- Нужен API, общий для браузера и Node (`TextEncoder`, `structuredClone`, `URL`, `console`), — объяви его тип точечно и запиши сюда, какой и зачем.
- Парсер и всё, что зависит от среды (загрузку wasm, файлы, таймеры), ядро получает аргументом от вызывающего.
- Синтаксис — тот, что Node исполняет без сборки: импорт своих файлов с `.ts`, типы через `import type`, только стираемый TypeScript, его проверяет `erasableSyntaxOnly` ([ADR-0014](../docs/adr/0014-backend-build-and-runtime.md)). Бэк в dev будет исполнять ядро так.
- Каждый модуль — свой подпуть: `@writechart/core/flowchart`. Общий `index.ts` с `export *` не заводи.
- Зависимости идут в одну сторону: фронт и бэк импортируют ядро, ядро берёт только свои файлы.
- Модель схемы, которая пойдёт по API, описывай Zod-схемой в `shared/`; ядро работает со своими типами.
- Тесты — `*.test.ts` рядом с кодом.
