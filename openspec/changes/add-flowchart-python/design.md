# Design

## Context

Мотивация — в proposal.md, требования — в `specs/flowchart-generation` и `specs/flowchart-editor`.

Стартовое состояние после `setup-core-scaffold`: пакет `core/` без сборки, `lib: ["ES2024"]`, `types: []`, правила синтаксиса Node, один тест-заглушка. Фронт — Vite 8 + React 19, страница `/` — заглушка `src/pages/home-page.tsx`. E2E собирает фронт и бэк и гоняет Chromium.

Замеры на грилинге 21.11.2026 (Node 24.22, Windows):
- `web-tree-sitter` 0.27.2 + `tree-sitter-python` 0.25.0: разбор 10 строк — 0,13 мс, 1000 строк — 6,6 мс, загрузка wasm — 25 мс. Вес gzip: JS ядра 32 КБ, wasm ядра 83 КБ, wasm Python 65 КБ.
- На коде без двоеточия у `if` tree-sitter теряет узел `if_statement` (узел `ERROR`); на незакрытой скобке всё дерево — ошибка. Поэтому любая ошибка разбора = нет новой схемы (требование «Ошибка в коде не даёт новой схемы»).
- dagre на `while` сдвигает тело вправо и рисует возврат косой линией — готовые раскладки не подходят.
- Узлы `tree-sitter-python` для нужных конструкций (выгрузка дерева): `module`, `expression_statement` → `assignment` / `augmented_assignment` / `call`, `pattern_list`, `if_statement` (условие, `block`, `elif_clause`, `else_clause`), `while_statement` (условие, `block`, `else_clause`), `comparison_operator` (цепочки `0 < i <= n` — один узел), `boolean_operator`, `not_operator`, `binary_operator`, `parenthesized_expression`, `string` (`string_start`, `string_content`, `interpolation` для f-строк), `keyword_argument`, `import_statement`, `pass_statement`, `comment`.
- `tree-sitter-python` не объявляет `exports`, wasm берётся по пути `tree-sitter-python/tree-sitter-python.wasm`; `web-tree-sitter` экспортирует `./web-tree-sitter.wasm`. При установке `tree-sitter-python` запускает `node-gyp-build` (нативный модуль для Node, нам не нужен).

Версии на 21.11.2026 по реестру npm (карантин Yarn `npmMinimalAgeGate` — сутки; при установке берём последнюю разрешённую и записываем сюда):

| Пакет | Версия | Где | Зачем |
|---|---|---|---|
| web-tree-sitter | 0.27.2 | frontend; core (dev) | разбор |
| tree-sitter-python | 0.25.0 | frontend; core (dev) | грамматика Python (wasm) |
| dompurify | 3.4.18 | frontend | очистка SVG перед вставкой |
| @fontsource/arimo | 5.3.0 | frontend; core (dev) | шрифт на странице; источник ширин букв |
| opentype.js | 2.0.0 | core (dev) | чтение шрифта скриптом генерации таблицы |
| @writechart/core | workspace | frontend | ядро |

## Goals / Non-Goals

**Goals:**
- Все требования двух спек, все проверки (`lint`, `format:check`, `deps`, `typecheck`, `test`, `build`, `e2e`) зелёные.
- Ядро не знает про tree-sitter, браузер и Node: другой язык потом — новый конвертер в ту же структуру.

**Non-Goals:**
- Всё из «Вне рамок» в proposal.
- Подсветка синтаксиса, клик по блоку ↔ строка кода.
- Оптимизация перерисовки: схема строится целиком на каждое изменение (у студента 10–200 строк, это меньше 3 мс разбора).

## Decisions

1. **Ядро не зависит от tree-sitter.** В `core/` описан минимальный интерфейс узла дерева (`type`, `text`, `children`, `namedChildren`, `childForFieldName`, `startPosition`, `isMissing`, `hasError`). Узел `web-tree-sitter` подходит под него по структуре. Ядро получает корень дерева аргументом.
   - Плюсы: в `core/` нет зависимостей времени выполнения; конвертер можно тестировать на любом дереве; смена парсера не трогает раскладку.
   - Вариант «ядро импортирует `web-tree-sitter` и само грузит wasm» отклонён: загрузка wasm разная в браузере и Node, а ядро — без API среды (ADR-0016).

2. **Конвейер ядра** (по подпутям, без `index.ts`):
   - `languages/python` — дерево разбора → структура; ошибки разбора и предупреждения.
   - `structure` — типы структуры: `Program { body }`, узлы `Process`, `Input`, `Output`, `If { condition, then, else }` (`elif` — `If` внутри `else`), `While { condition, body }`, `Unsupported { keyword, firstLine }`. У каждого узла — строки кода (`line`). Текст выражений хранится уже в математической записи как список частей (обычный текст, надстрочный текст, текст в «ёлочках»), не строкой.
   - `notation` — перевод выражений Python по таблице из спеки.
   - `layout` — структура → чертёж: фигуры (вид, x, y, ширина, высота в мм, строки текста) и линии (точки, стрелка да/нет, подпись).
   - `render-svg` — чертёж → строка SVG через строитель.
   - `gost-check` — чертёж → список нарушений.
   - `fonts/arimo` — таблица ширин букв.
   - `flowchart` — одна функция для фронта: дерево + параметры → `{ svg, warnings, errors }` или ошибка.
   - Раскладку `core/src/` записываем в `core/AGENTS.md`.

3. **Раскладка — вложенные коробки** (решение человека Q8). Каждая конструкция возвращает коробку: ширина, высота, x оси входа, x оси выхода, отступ возврата слева, отступ «нет» справа. Родитель ставит коробки детей по правилу:
   - последовательность — друг под другом на общей оси, между фигурами — вертикальный промежуток;
   - `if` — ромб; ветка «да» под ромбом на оси; ветка «нет» справа, её ось правее правого края ветки «да» на промежуток; слияние — горизонтальная линия справа налево в ось со стрелкой;
   - `while` — ромб; тело под ним; возврат: вниз от тела, влево на отступ возврата, вверх, вправо в линию над ромбом со стрелкой; выход «нет»: вправо от ромба на отступ «нет» (правее тела), вниз, влево в линию под циклом со стрелкой. Отступ возврата внешнего цикла = отступ внутреннего + шаг;
   - в конце обход дерева раздаёт абсолютные координаты, схема сдвигается так, чтобы левый верхний край был у поля.
   - Правило стрелок — параметр: функция «линия → ставить стрелку?». По умолчанию — последний отрезок влево или вверх.

4. **Размер символа.** Текст разбивается на строки по пробелам (слово длиннее строки режется по буквам). Перебираем `a` = 10, 15, 20 … мм, `b = 1,5a`; берём первую, где строки помещаются во внутреннюю область символа с полями. Внутренняя область: прямоугольник — весь минус поля; параллелограмм — минус скосы; ромб — вписанный прямоугольник `b/2 × a/2`; терминатор — минус полукруги.

5. **Ширина текста — таблица Arimo в ядре** (Q10, Q11). Скрипт `core/scripts/generate-font-metrics.ts` (Node, запускается руками) читает файлы `@fontsource/arimo` (латиница и кириллица, начертание 400) через `opentype.js` и пишет `core/src/fonts/arimo.ts`: `unitsPerEm` и ширину каждого символа, плюс ширину по умолчанию для символов не из таблицы. Результат коммитим. Кернинг не учитываем: поле внутри символа берём с запасом. Шрифт — параметр раскладки (таблица + имя `font-family`), в первой версии одна таблица.
   - `opentype.js` читает WOFF; если в `@fontsource/arimo` нет файлов WOFF нужных наборов — берём `fontkit` (читает WOFF2) и записываем замену сюда.

6. **SVG — строитель с белым списком** (Q9). Функция `el(имя, атрибуты, дети)`: имя только из списка спеки, атрибуты только из списка (`x`, `y`, `width`, `height`, `d`, `points`, `transform`, `fill`, `stroke`, `stroke-width`, `stroke-dasharray`, `font-family`, `font-size`, `text-anchor`, `dominant-baseline`, `baseline-shift`, `viewBox`, `xmlns`, `data-block-id`), значения и текст экранируются (`& < > " '`). Иначе — исключение. Склеивать SVG шаблонными строками с текстом пользователя запрещено: это правило в `core/AGENTS.md`. Корень: `width`/`height` в мм, `viewBox` в мм. Надстрочный текст — `tspan` с `baseline-shift="super"` и меньшим кеглем. Символы U+202A–U+202E и U+2066–U+2069 заменяются меткой `⟨U+202E⟩`.

7. **Ошибки разбора.** Если у корня `hasError`: собираем узлы `ERROR` и пропущенные (`isMissing`) с их строками. Для пропущенного — «Строка N: не хватает «X»» (X — тип пропущенного узла, например `:`), для `ERROR` — «Строка N: ошибка в коде». Схему не строим.

8. **Что не рисуется.** `import`, `from … import`, комментарии и `pass` в схему не попадают и предупреждений не дают: это не шаги алгоритма. **Предложение агента — подтвердить на ревью.** `while … else` — неподдерживаемая конструкция.

9. **Лимиты** проверяет ядро: длина кода — до разбора (во фронте, ядро повторяет для чужих вызовов), глубина и число блоков — при обходе. Значения — в таблице ниже.

10. **Фронт: воркер.** `src/features/flowchart/flowchart.worker.ts` (Vite: `new Worker(new URL(...), { type: "module" })`): при первом сообщении грузит `web-tree-sitter` и грамматику (`?url`-импорты wasm, `Parser.init({ locateFile })`), на каждое сообщение — разбор, вызов ядра, ответ `{ svg, warnings, errors }`. Хук `useFlowchart(code)` отправляет последний код; если ответа нет 2 с — `terminate()`, новый воркер, сообщение «Схема строится слишком долго». Пока воркер занят, промежуточные правки не копятся: отправляется только последний код.
    - Сверить `Parser.init`, `locateFile`, `Language.load` через Context7 перед кодом.

11. **Фронт: вставка SVG.** `DOMPurify.sanitize(svg, { USE_PROFILES: { svg: true } })` → контейнер через `dangerouslySetInnerHTML`. Второй слой к белому списку ядра. Шрифт: `import "@fontsource/arimo/cyrillic-400.css"` и `latin-400.css` в странице схемы.

12. **Фронт: поле кода.** Компонент `code-input.tsx`: `<textarea>` + колонка номеров строк (прокрутка синхронна), Tab/Shift+Tab (4 пробела), выделение номеров строк с ошибкой. Без зависимостей. Тест компонента (RTL): Tab вставляет 4 пробела, номера строк растут с числом строк.

13. **Тесты ядра.**
    - Тестам нужен настоящий разбор: `web-tree-sitter` и `tree-sitter-python` в dev-зависимостях `core/`, wasm грузит вспомогательный файл тестов через Node.
    - Поэтому `core/` получает два tsconfig, как фронт: `tsconfig.lib.json` (`src/**`, кроме тестов; `lib: ["ES2024"]`, `types: []`) и `tsconfig.test.json` (тесты и `scripts/`; `types: ["node"]`, `@types/node` в dev). `tsconfig.json` — `references` на оба, `typecheck` → `tsc -b`. Так код ядра по-прежнему без Node, а тесты и скрипт — с ним.
    - Слои (Q21): (1) код → структура, включая перевод текста — по сценариям спеки; (2) `gost-check` на всех примерах даёт ноль нарушений и находит намеренно испорченный чертёж; (3) эталоны: `toMatchFileSnapshot` в `core/src/__snapshots__/*.svg` для набора программ (по одной на сценарий спеки + 3 программы по мотивам лаб человека); (4) атаки из спеки — в SVG нет запрещённых элементов и атрибутов. Детерминизм — генерация дважды даёт одинаковый SVG.
    - Скилл `tdd`: граница теста — функция `flowchart` и отдельные шаги конвейера; red → green на каждом сценарии.

14. **Проверка правил ГОСТ** (`gost-check`): только разрешённые символы; `b = 1,5a`, `a` кратно 5 и ≥ 10; у ромба ровно два выхода, «да» и «нет»; у каждой фигуры, кроме «Начала», есть вход, кроме «Конца» — выход; отрезки только горизонтальные и вертикальные; стрелки по правилу; фигуры не пересекаются; линии не проходят сквозь фигуры; текст помещается в фигуру. Возвращает список `{ правило, фигура или линия, текст }`.

15. **Нативная часть tree-sitter не собирается.** В корневом `package.json`: `"dependenciesMeta": { "tree-sitter-python": { "built": false } }` (Yarn читает `dependenciesMeta` только в корне). Проверка: `yarn install` не запускает `node-gyp-build`.

16. **E2E** `e2e/tests/flowchart.spec.ts`: открыть `/` → в схеме есть «Начало», «Конец», «да», «нет»; заменить код на `while i <= n` без двоеточия → видна «схема устарела» и сообщение со строкой; вернуть двоеточие → пометки нет; код с `<img src=x onerror=alert(1)>` → диалога нет. Элементы — по роли и тексту.

17. **Документация.**
    - ADR-0017 «Парсер — tree-sitter»: Lezer, tree-sitter, ANTLR, свой — с замерами грилинга (вес, скорость, ошибки при наборе, популярность, сопровождающие); решение человека — tree-sitter (команда, доверие сообщества).
    - ADR-0018 «Схема: структура → чертёж → SVG, своя раскладка»: два шага модели, своя раскладка (замер dagre, вес ELK), SVG в ядре, мм, таблица шрифта, защита SVG.
    - `docs/architecture.md`: раздел «Устройство схем» (конвейер, где что работает), строка статуса в начале, «Отложено» — редактор, CSP страниц (`script-src 'self'`, `'wasm-unsafe-eval'`, `worker-src`), заголовки экспорта (`attachment`, `CSP: sandbox`).
    - `core/AGENTS.md` (раскладка `src/`, строитель SVG обязателен, интерфейс узла, как перегенерировать таблицу шрифта, эталоны SVG), `frontend/AGENTS.md` (воркер, wasm, DOMPurify обязателен, папка `src/features/`).

18. **Скиллы.** `tdd` (ядро), `codebase-design` (границы модулей ядра), `vercel-react-best-practices` (страница, хук), `playwright-cli` (E2E), `writing-for-agents` (AGENTS.md), `security-review` перед «готово».

## Risks / Trade-offs

- [`web-tree-sitter` 0.27 и грамматика 0.25 несовместимы по ABI] → замер на грилинге прошёл на этой паре. Если при установке версии другие — проверяем тестами ядра, при ошибке закрепляем пару из таблицы.
- [Vite не отдаст wasm или воркер в `vite preview` / E2E] → E2E ловит это сразу. Смягчение: `?url`-импорт wasm — стандартный путь Vite; при проблеме — копия wasm в `public/` с записью сюда.
- [Типы `web-tree-sitter` тянут DOM] → ядро их не импортирует (решение 1), фронт DOM и так видит.
- [Ширины без кернинга] → текст может быть чуть уже расчёта; поля с запасом, тест «текст помещается» в `gost-check`.
- [`dependenciesMeta built: false` не сработает] → задача проверяет лог `yarn install`; при неудаче — `enableScripts` не трогаем, пишем вопрос человеку.
- [Детерминизм SVG] → числа округляем до 0,01 мм, порядок элементов задаёт обход; тест сравнивает два прогона.
- [tree-sitter теряет конструкцию при ошибке] → по спеке при любой ошибке новой схемы нет, на экране последняя удачная (Q18).
- [Эталоны SVG меняются на каждую правку раскладки] → это и цель: разница видна в PR, человек принимает её глазами.
- [Вес страницы] → wasm и tree-sitter грузятся в воркере, страница показывается раньше; разбить загрузку сильнее — потом, если понадобится.
