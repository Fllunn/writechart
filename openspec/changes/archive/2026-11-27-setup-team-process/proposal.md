# Proposal

## Why

В команде 4 человека, но процесс в репозитории описан для одного: «человек утверждает proposal», «одобрения не требуются». Задач на доске нет, и не видно, кто что взял. Уже есть две ветки на одну работу (`feat/add-flowchart-python` и `feat/finish-flowchart-python`). Правила команды решены и теперь записываются в репозиторий, чтобы их знали и люди, и агенты.

## What Changes

- **Задачи** живут в GitHub Issues и на доске GitHub Projects с колонками Backlog → In progress → In review → Done. Один issue = одно изменение OpenSpec = одна ветка = один PR. Proposal и код лежат в одной ветке, задача проходит доску один раз.
- **Как взять задачу:** поставить себя в Assignee и перевести карточку в In progress, только потом создавать ветку. Если у задачи уже есть исполнитель, её не трогают, а пишут исполнителю. Жёстких ролей и лимита задач нет.
- **Ревью:** proposal утверждает автор задачи своему агенту, без PR. PR целиком (proposal + код) утверждает любой член команды, кроме автора, через approve. Обязательный approve уже включён в ruleset `master`. **Меняется правило** ADR-0010 «одобрения не требуются».
- **Слияние:** сливает автор, когда есть approve и CI зелёный. Архив OpenSpec кладётся последним коммитом. В тексте PR пишется `Closes #N`.
- **Метки:** по пакету (`core`, `frontend`, `backend`, `shared`, `e2e`, `ci`, `docs`) и по типу (`feat`, `fix`, `chore`).
- Новые файлы: `CONTRIBUTING.md`, `docs/adr/0019-team-process.md`, `.github/ISSUE_TEMPLATE/task.yml`.
- Правки: `AGENTS.md` (раздел «Как работаем», «Процесс»), `.github/pull_request_template.md` (строка `Closes #`), `README.md` (ссылка на `CONTRIBUTING.md`), `docs/architecture.md` (строки про Git и OpenSpec), `docs/adr/0010-git-process.md` (пометка о замене в статусе), `docs/adr/README.md` (строка 0019, статус 0010).

Вне рамок:
- Заводить issues, метки и настраивать доску: это делает человек в GitHub, агент только готовит тексты.
- Сроки и вехи (milestones): команда решила их не вести.
- Пропуск строк 0017 и 0018 в `docs/adr/README.md`: найдено попутно, исправляется отдельно.

## Capabilities

### New Capabilities

Нет. Меняются только документация и шаблоны GitHub, поведение системы остаётся прежним, поэтому `skip_specs: true`.

### Modified Capabilities

Нет.

## Impact

- Только документы и шаблоны: `CONTRIBUTING.md`, `AGENTS.md`, `README.md`, `docs/`, `.github/`.
- Код, зависимости и CI не меняются.
- Агенты: перед работой спрашивают номер issue и предлагают `Closes #N` в тексте PR. Issues сами не заводят, это по-прежнему действие человека в GitHub (ADR-0011).
