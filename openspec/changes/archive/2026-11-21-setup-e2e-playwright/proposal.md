# Proposal

## Why

Фронт и бэк есть, но вместе их никто не проверяет: Vitest гоняет каждый пакет отдельно. Сборка фронта, прокси `/api`, сборка бэка и база могут сломаться на стыке, и это увидят только руками. ADR-0009 выбрал Playwright для E2E главных сценариев, теперь его пора поставить, пока сценариев мало.

Это третье из трёх изменений (решение человека): фронт → бэк → Playwright.

## What Changes

Все решения ниже — решения человека в допросе перед этим изменением (20.11.2026).

- **Пакет `e2e/`** (`@writechart/e2e`) — четвёртый воркспейс, как советует гайд Turborepo по Playwright.
- **Весь стек:** тест поднимает собранный фронт (`vite preview`) и собранный бэк (`dist/server.js`) с базой `writechart_test`.
- **Свои порты:** фронт 4173, бэк 3100; чужой запущенный сервер (например, `yarn dev`) тест не берёт.
- **Только Chromium** (headless shell).
- **Два теста:** главная показывает заголовок; `GET /api/health/ready` через адрес фронта отвечает 200 по схеме `ReadyResponse` из `shared`.
- **Повторы и trace как в шаблоне Playwright:** в CI 2 повтора, trace на первом повторе, забытый `test.only` роняет CI.
- **Отчёты:** в CI — аннотации `github` и HTML-отчёт; при падении отчёт сохраняется артефактом на 14 дней.
- **Turborepo:** задача `e2e` (зависит от сборки фронта и бэка, кэш как у `test`), корневая команда `yarn e2e`.
- **CI:** своя задача `e2e` в `ci.yml`, параллельно с `check`, со своим сервисом Postgres; браузер ставит `playwright install --with-deps chromium --only-shell`. Человек добавляет `e2e` в обязательные проверки `master`.
- **Линтер:** Oxlint как есть, плюс `env.node` для `e2e/**`. Забытый `await` уже ловит `typescript/no-floating-promises`.
- **Документация:** `AGENTS.md` (команда `yarn e2e` и разовая установка браузера, `yarn e2e` в проверках перед «готово»), новый `e2e/AGENTS.md`, `frontend/AGENTS.md`, `docs/architecture.md`. Нового ADR нет: Playwright уже выбран в ADR-0009.
- **Правило про секреты в `AGENTS.md`** (решение человека при реализации 20.11.2026): агент не переносит и не правит `.env`, проверки без файла — через переменные окружения. Причина — потерянный при реализации `.env` (design, риски).

Вне рамок: Firefox и WebKit, Docker-образ Playwright, отдельная база для E2E и очистка базы (вместе с ORM), плагин `eslint-plugin-playwright`, сценарии продукта, новый код во `frontend/` и `backend/`, кэш браузеров в CI, деплой.

## Capabilities

### New Capabilities

Нет. Два теста проверяют уже описанное поведение (`specs/api-health`) и заглушку главной, новых требований к системе нет. Поэтому `skip_specs: true`, как в прошлых изменениях по инструментам.

### Modified Capabilities

Нет.

## Impact

- Новые файлы в `e2e/`: `package.json`, `playwright.config.ts`, `tsconfig.json`, тесты, `AGENTS.md`.
- Новые зависимости только в `e2e/package.json` (список и версии в design).
- Правки: корневой `package.json` (воркспейс `e2e`, скрипт `e2e`), `turbo.json` (задача `e2e`), `.oxlintrc.json`, `.github/workflows/ci.yml` (задача `e2e`), `yarn.lock`, `AGENTS.md`, `frontend/AGENTS.md`, `docs/architecture.md`.
- Локально `yarn e2e` требует `docker compose up -d` и один раз скачанный Chromium (126 МБ).
- В CI появляется вторая задача; время до зелёной галочки почти не растёт, она идёт параллельно с `check`.
- Человек: добавить проверку `e2e` в правила защиты `master` на GitHub.
